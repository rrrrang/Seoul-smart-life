## 구현 중 내린 판단과 영향

1. 승인된 별도 작업 사본/브랜치를 재사용했습니다. 다른 사용자 작업 사본을 덮어쓰지 않습니다. 잘못된 경로로 재개하면 변경을 놓칠 수 있어 현재 경로를 보고서에 명시했습니다.
2. skill Bash helper의 basename 실행 실패로 Python 작업 요약/진행 기록을 사용했습니다. 제품 기능에는 영향이 없으며 검토 기록을 보고서에 남겼습니다.
3. 환경 테스트에 필요한 connection.py만 Task2에서 Task1로 앞당겼습니다. 초기화 책임은 명시적 CLI/스키마에 유지했습니다. 테스트 순서만 달라집니다.
4. 점수 연결 테이블에 sigungu_code와 복합 FK를 추가하여 다른 구 점수의 오연결을 DB에서도 거부했습니다. 새 적재자는 이 열과 FK 계약을 따라야 합니다.
5. PostgreSQL의 길이 초과 값 거부가 DataError일 수 있어 해당 테스트가 DataError 또는 IntegrityError를 허용하도록 했습니다. 거부 자체는 필수로 검증하며 두 클래스의 차이를 진단하지는 않습니다.
6. 환경 fixture가 스키마를 소비해 Task1+2를 한 로컬 커밋으로 저장했습니다. 기능 범위 영향은 없고 커밋 분리 단위만 달라집니다.
7. Windows 일반/승격 실행 사용자 간 TEMP 권한 충돌을 피하려고 테스트만 새 .test-tmp 경로와 비활성 pytest cache를 사용했습니다. 제품 동작은 바뀌지 않으며 실행자가 다른 환경에서는 이 우회가 불필요할 수 있습니다.
8. DB application을 최상위 facade에서 자동 import하지 않았습니다. 파일 단독 사용자에게 SQLAlchemy를 강제하지 않으며 DB 사용자는 명시적 application import 경로를 씁니다.
9. CUA/node_repl의 kernel asset 초기화 실패로 설치된 Playwright와 Edge의 독립 임시 프로필로 검증했습니다. 앱 내 브라우저 자체 검증과 Kakao 실 SDK 확인은 이를 통해 증명하지 않습니다.
10. 기존3패널 구성을 유지하고 입력/버튼/출처의 여백을 CSS로 보완했습니다. 시각 차이는 브라우저로 확인했으며 사용자 디자인 추가 검토는 가능합니다.
11. 기존 Windows CRLF 파일 전체를 재작성하지 않고 프론트 whitespace=cr-at-eol 속성을 적용했습니다. 실제 스페이스 오류 검사는 유지하고 CR 문자를 줄끝으로 인정합니다. 영향은 공백 진단 기준입니다.
