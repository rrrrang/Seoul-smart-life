경제활력도 현재월 추정 모델 설계
작성일: 2026-10-21 / 대상: 서울 427개 프로젝트 행정동 / 제공월: 2026-10

1. 무엇을 계산하는가

해당 행정동에 출근 활동, 공개 법인사업장 고용, 음식·생활서비스 등록 영업기반이
면적 대비 얼마나 집중되어 있는지를 0~100점으로 표현합니다.
정답을 '매출액'이나 '주민 소득'으로 놓고 학습하지 않습니다.
실제 관측이 아직 없는 현재월의 세 축 값을 먼저 추정한 뒤, 고정 점수식에 넣습니다.
경제 전반의 모든 활동을 측정하는 지수나 거주민 소득·집값·성장률 지표가 아닙니다.

2. 입력 데이터와 가중치

축                 원값                                      마지막 관측월  가중치
출근 활동          평일 출근 목적 도착 이동량의 일평균          2026-09       1/3
공개 법인 고용     공개 국민연금 법인사업장 가입자 수 합계       2026-08       1/3
등록 영업기반      5개 업종의 등록 영업후보 건수                 2026-09       1/3

5개 업종은 일반음식점·휴게음식점·제과점·미용업·세탁업입니다.
법인 공개사업장 가입자 수는 전체 종사자 수가 아니며 거주민 고용률도 아닙니다.
출근 목적 이동량은 전체 유동인구가 아닙니다.
등록 영업후보는 인허가/폐업일 등을 이용해 복원한 기록수이며 현장 영업 확인값이 아닙니다.
월별 입력: 2024년 8월~2026년 9월(26개월), 고용 관측은 2026년 8월까지(25개월).
공식면적: 2025년 말 기준 고정값. region_code는 프로젝트 6자리 문자열, 자치구는 5자리입니다.

3. 현재월 값 추정

(A) 출근 활동: 최근 관측 가능한 3개월 밀도의 중앙값.
    예: 최근 유효값이 90, 110, 100이면 추정 밀도는 100입니다.
    단순 최신값·Ridge·XGBoost와 과거 개발 구간에서 비교한 결과 선택된 규칙입니다.

(B) 공개 법인 고용: 가장 최근 관측된 밀도를 유지합니다.
    10월 추정에서 8월 값을 씁니다. 새로운 고용 증가를 안다고 가정하지 않습니다.

(C) 등록 영업기반: XGBoost 예측 50% + 가장 최근 관측 밀도 50%.
    학습 목표 = log1p(다음 달 밀도) - log1p(관측 밀도).
    XGBoost가 예측한 변화량을 최신 관측 밀도에 적용하고 원단위로 복원합니다.
    최종 예측 밀도 = 0.5 × XGBoost 예측 밀도 + 0.5 × 최신 밀도.
    3회 미만 관측한 동은 최신값을 사용합니다.

XGBoost 입력 17개
  현재 log밀도, log면적, 유효관측 횟수, 최근3개 중앙값의 log,
  전년 같은 대상월 log밀도, 대상월 sin/cos,
  1·2·3·6·12개월 전 log밀도와 각각 현재값 대비 변화.
학습 중 과거 lag가 없는 부분은 학습 자료의 중앙값으로 채우고 결측 여부 입력을 추가합니다.
최신 필수 관측 자체가 누락된 경우에는 예측을 거부합니다.
행정동 코드를 숫자 크기나 순서의 의미를 가진 예측변수로 넣지 않습니다.

XGBoost 설정
  n_estimators=180, max_depth=3, learning_rate=0.035, min_child_weight=25,
  subsample=0.9, colsample_bytree=0.9, reg_lambda=20,
  objective=reg:squarederror, tree_method=hist, n_jobs=2, random_state=20261021.
현재 제공 모델은 2026-09까지 알려진 학습 정답을 사용합니다.
월 경계를 지켜 검증했으며, 대상월 정답이나 이후 월 데이터를 학습 입력으로 넣지 않습니다.

4. 세 축을 점수로 바꾸는 고정 계산식

밀도 = 원값 ÷ 행정동 면적(km2)
축 점수 = 100 × clip((log1p(추정 밀도) - L) ÷ (U - L), 0, 1)
경제 점수 = (출근 축 점수 + 고용 축 점수 + 영업기반 축 점수) ÷ 3

L/U는 매월 새로 계산하지 않습니다.
2024-08~2025-05 각 동의 log밀도 중앙값을 구한 후 동 간 하위5%/상위95%로 고정했습니다.
출근 L=7.0105068076596275, U=10.063686133786627
고용 L=5.6364623310375, U=10.233176976869283
영업기반 L=4.126364042227578, U=6.962262552395443
같은 밀도는 어느 달에도 같은 축 점수입니다. 상·하단을 넘으면 100/0으로 제한되어
해당 구간의 세부 차이는 표현되지 않습니다. 점수는 서울 내 고정 기준의 상대 척도입니다.

5. 자료 정비와 제외 규칙

동 코드와 주소 근거를 확인한 경우만 국민연금·인허가 행정동 연결을 보완했습니다.
공개범위 변경 영향을 줄이기 위해 고용은 법인 공개사업장 정의로 유지합니다.
2025-03/04 출근자료는 기준 이상이 해소되지 않아 입력 이력에서 제외합니다.
2025-08 이전 신설동·용두동의 분리값은 확인되지 않아 임의 분배하지 않습니다.
고용은 2025-12 이전 코드변경을 가로지르는 학습쌍을 사용하지 않고 이후 이력을 구분합니다.
단, 선택된 고용 모델은 최신값 유지여서 추가 학습 모델이 없습니다.
큰 정상값을 임의 축소하지 않습니다. 누락된 자료를 0으로 채우지 않습니다.
현재 입력의 지역·면적·학습 모델 해시는 model_config.json에서 검사합니다.

6. 검증한 성능과 사용 범위

모델 선택 개발 구간: 2025-09~2026-05. 재검증 구간: 2026-06/07/08, 427동×3개월=1,281건.
자료 정비 뒤 같은 정답·같은 행을 기준으로 비교했으며, 이미 봤던 과거 자료의 재검증입니다.

월           현재 모델 MAE     최신값 유지 MAE
2026-06       0.60885            0.97340
2026-07       0.53183            0.48311
2026-08       0.60413            0.57407
3개월 평균    0.58161            0.67686

평균 점수오차가 약14.1% 감소했지만 매월 항상 이긴 것은 아닙니다.
월별 RMSE 평균은 모델0.94037, 기준0.93482로 모델이 약간 더 나쁩니다.
방향 균형정확도는 모델43.46%, 기준51.23%입니다. 따라서 상승·하락 예측을 제공하지 않습니다.
0.58점 오차를 99.42% 정답률이라고 해석하지 않습니다.

현재월 경제활동 수준을 참고용 추정점수로 표시하는 실행 경로를 제공합니다.
장기간 실제 공개시점 자료로 운영한 검증, 경제 전체를 대표하는 타당성 검증은 남아 있습니다.
인허가 과거주소·휴업/재개업 이력이 없고 일부 주소 연결은 미확정입니다.
큰 개별 오차와 상하단 점수 포화가 있으므로 소수점 차이로 동네의 우열을 단정하지 않습니다.

7. 경제 5등급

점수에 20점 간격 고정 구간을 적용하며, 등급별 동 수를 같게 나누지 않습니다.
1등급 80~100 / 2등급 60 이상 80 미만 / 3등급 40 이상 60 미만 /
4등급 20 이상 40 미만 / 5등급 0 이상 20 미만입니다. 반올림 전에 판정합니다.
2026-10 분포: 1등급 47개, 2등급 92개, 3등급 129개, 4등급 104개, 5등급 55개.
높은 등급은 경제활동 집중도 추정점수가 높다는 뜻입니다. 점수나 모델은 변경하지 않습니다.
items[].metadata.economy.grade와 grade_label, root.metadata.economy.grade_rules로 전달합니다.

8. 서비스 전달과 갱신

JSON의 scores.economy를 사용하고 metadata.economy.status='estimated' 및 대상월을 표시합니다.
다른 도메인의 null은 아직 계산하지 않은 값입니다. 0점이 아닙니다.
2026-10-21 이전 기준일 또는 2026-11 이후 대상월은 현재 제공본에서 거부합니다.
다음 달에는 새 원천월 입력 확인 → 인허가 재학습 → 최신 관측월 재검증 → 새 제공본 확정이 필요합니다.
재학습·추정 코드는 포함하지만, 수집 자동화·서비스 서버 배포는 이 패키지의 역할이 아닙니다.
메인 백엔드의 10자리 목록은 이 결과와 직접 조인되지 않습니다. 6자리 프로젝트 코드 계약을 사용합니다.
